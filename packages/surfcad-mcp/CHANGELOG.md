# Changelog

## Unreleased

- Safari (macOS) can pair. The relay serves a small **SurfCAD local agent bridge** page at `http://127.0.0.1:17341/bridge`; SurfCAD opens it as a pop-up from **Connect Agent** and passes relay traffic through it, because Safari blocks `ws://127.0.0.1` from https pages. The page only talks to allowlisted SurfCAD origins, needs a per-session nonce, cannot be framed, and answers only for a loopback `Host`. If the relay is not running yet, the window keeps retrying (every few seconds, no time limit) and connects once `npx surfcad-mcp` starts. Tab reconnects reuse that same window — they do not open a new one. Pairing still needs **Allow connection** in SurfCAD. Safari on iPhone and iPad is still not supported.
- `AgentBridgeHost` is mounted once above App's desktop/mobile split, so a 768px resize does not remount the pairing socket or mint a new `tabKey`.
- Dropped-tab reservations now expire in `hasTab` / `liveTab` (24 h TTL) and an unref'd sweep drops stale Map entries; a later `register_tab` can reuse the code.
- Pairing Allow uses the shared `surface-success` class (`text-on-dark` contrast ≥4.5:1 rest, ≥3:1 hover) instead of `hover:bg-emerald-500`.
- Fixed: when the SurfCAD tab's socket dropped mid-session, the next tool call hung until the MCP client timed out (`-32001`), and later calls failed with `pair_failed` ("No SurfCAD tab is advertising this pairing code"). Tool calls now return `pairing_lost` within about a second while the link is down, with the hint "Open SurfCAD in Chrome and keep the tab open; it will reconnect." A call already in flight is rejected the same way.
- The connection now recovers by itself. The tab reconnects with backoff (and right away when it becomes visible or goes back online), and the server re-pairs with the same code in the background. On Allow the hub stores `{resumeKey, tabKey}` and never forwards the resume secret on `PAIR_REQUEST`; a matching resume from that same `tabKey` auto-pairs at the hub (the tab sees `resume: true`). After a drop the pairing code stays reserved for that `tabKey` (24 h), so another loopback client gets `token_in_use` instead of the secret. A different client with the same code still has to be allowed in SurfCAD. If the process that owned the relay exits, another running `surfcad-mcp` takes over the port. Closing the account panel, or crossing 768px, does not drop the pairing: `AgentBridgeHost` is mounted once on App above the desktop/mobile split. Allow/Deny is a `document.body` portal, so a pairing request still prompts when the menu is closed.
- The loopback probe tells a visible HTTP 403 Origin rejection apart from a timeout. CORS-hidden opaque OK on https is `browser_blocked` (Chrome Local Network Access looks the same), not `origin_rejected`. Timeouts stay `issue: null` so polling continues.
- The relay pings every socket every 5 s and drops any socket that misses a ping (`SURFCAD_AGENT_BRIDGE_HEARTBEAT_MS` to tune it). Drops, heartbeat timeouts and pairing ends are logged on stderr with a timestamp and reason. Pairing codes are redacted and secrets are never logged. Relay logging no longer writes to stdout, where verbose mode used to corrupt the MCP stdio stream.
- `unknown_token` is now reported as `unknown_token` (it used to come back as `pair_failed`). A bridge call that has to pair first waits at most about a second for Allow, then returns `pair_pending`. The `pair` tool returns `pair_pending` after 30 s instead of running into the client timeout.
- New `rename_part` tool `{ part_id, name }`. A vault part also moves its `.js` path in the same folder (`-2`, `-3` on collision) and updates the `.surf.json` in one commit. Unknown ids return `unknown_part`.
- `git_save` saves like the app's Save button: parts without a vault path get one, and those scripts plus the `.surf.json` land in one commit. It no longer returns `no_repo_path`. The app promotes those paths once (in `assembleCommitFiles`) and adopts the result, so a second Save does not mint `-2` copies. A failed `listTree` aborts instead of occupying nothing. Occupancy includes `.mesh` siblings.
- `git_add_to_repo` works on a multi-part assembly whose other parts have no paths. They are pathed and committed with it instead of failing `.surf.json` validation on every call.
- Git writes on a real repo return `consent_pending` immediately (with `details.retry` and `details.retry_after_ms`) while the consent dialog waits, instead of blocking until the MCP client times out (`-32001`). Retry after the user clicks Allow. Headless tabs and a denied session still return `real_repo_blocked`.
- `create_part` in a git assembly no longer commits on its own; `git_save` writes it behind the consent dialog.

## 0.2.0

- `npx surfcad-mcp` starts (or reuses) the loopback agent-bridge relay on `127.0.0.1:17341` so production https://surfcad.com tabs can pair without the Vite dev server.
- Safari is not supported yet: it blocks `ws://127.0.0.1` connections from https pages.
